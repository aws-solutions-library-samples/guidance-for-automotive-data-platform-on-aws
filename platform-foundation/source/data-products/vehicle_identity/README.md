# Vehicle Identity Graph (`vehicle_identity`)

> **Domain**: Automotive &nbsp;·&nbsp; **Storage**: Iceberg
> &nbsp;·&nbsp; **Display name**: `Vehicle Identity Graph`

One row per VIN — make, model, trim, model year, body style, drive
type, powertrain type, plus the EV-specific covariates (battery
chemistry, pack capacity, motor count, max charging rate, connector
type, EPA range) that downstream products use to explain telemetry,
charging behavior, and energy efficiency. Producer is
[`generator.py`](generator.py) (pandas tier, 1:1 with the `vins`
dimension); column formats follow
[`docs/data-contracts.md`](../../../../docs/data-contracts.md).

## Schema

| Column | Type | Nullable | Description |
|---|---|---|---|
| `vin` | string | no | VIN (PK, 1:1 to `vins`); regex per [data-contracts](../../../../docs/data-contracts.md#identifier-formats) |
| `model_year` | int | no | Vehicle model year (2018–2030). **Partition key** |
| `make` | string | no | Manufacturer (`Acme Motors` only in v1) |
| `model` | string | no | Model name |
| `trim` | string | yes | Trim level |
| `body_style` | string | no | enum: `sedan` / `suv` / `truck` / `hatchback` / `coupe` |
| `drive_type` | string | no | enum: `awd` / `fwd` / `rwd` |
| `powertrain_type` | string | no | enum: `electric` / `hybrid` / `erev` |
| `battery_chemistry` | string | yes | enum: `nca` / `ncm` / `lfp` / `lto` |
| `battery_pack_kwh` | double | no | VSS `.GrossCapacity` (40–250 kWh) |
| `battery_net_kwh` | double | no | VSS `.NetCapacity` (40–250 kWh) |
| `motor_count` | int | no | Number of traction motors (1–4) |
| `max_charging_rate_kw` | double | no | VSS `.MaximumChargingCurrent.DC` equivalent (50–400 kW) |
| `connector_type` | string | no | enum: `J1772` / `CCS1` / `NACS` / `CHAdeMO` |
| `range_epa_mi` | double | no | EPA-rated range (US `_mi` deviation, 100–800 mi) |
| `assembly_plant` | string | yes | Assembly plant code |
| `manufacture_date` | date | no | Vehicle manufacture date |
| `build_software_version` | string | yes | Factory-installed software (semver) |
| `current_software_version` | string | yes | Latest installed software (semver, post-OTA) |
| `vss_version` | string | no | VSS catalog version applicable to this vehicle |

## Partition keys

- **Partition**: `model_year` — small cardinality (13 values for
  2018–2030); produces ~5M / 13 ≈ 380K rows per partition at full
  scale, well-shaped for Iceberg metadata.
- **No bucketing**: 5M rows total is small enough that
  partition-level parallelism alone covers query patterns.
- **Pruning**: filter on `model_year` for cohort analysis;
  point-lookups on `vin` are PK and don't need partition prune.

## Sample queries

Fleet composition by powertrain × battery-chemistry, model years
2024+:

```sql
SELECT powertrain_type,
       battery_chemistry,
       COUNT(*)              AS vins,
       AVG(battery_pack_kwh) AS avg_pack_kwh,
       AVG(range_epa_mi)     AS avg_range_mi
FROM   adp_staging_vehicle_identity.vehicle_identity
WHERE  model_year >= 2024
GROUP BY powertrain_type, battery_chemistry
ORDER BY vins DESC;
```

Connector-type readiness — what fraction of the fleet can take a
NACS-only public DC fast station today:

```sql
SELECT connector_type,
       COUNT(*)                        AS vins,
       AVG(max_charging_rate_kw)       AS avg_max_kw,
       100.0 * COUNT(*) / SUM(COUNT(*)) OVER () AS pct_of_fleet
FROM   adp_staging_vehicle_identity.vehicle_identity
GROUP BY connector_type
ORDER BY vins DESC;
```

Cross-product joins (VIN-full-360, OTA × identity targeting analysis)
live in
[`docs/cvx-integration-contract.md` § 4](../../../../docs/cvx-integration-contract.md)
and the standalone files under
[`platform-foundation/source/athena-queries/`](../../athena-queries/).

## Lineage

- **Inputs**:
  - `vins` dimension (5M, 1:1) — generated by
    [`platform-foundation/source/dimensions/generate_all.py`](../../dimensions/generate_all.py).
- **Producer**: [`generator.py`](generator.py) (pandas, ports the
  legacy generator from `guidance-for-vehicle-knowledge-base/scripts/
  generate-vehicle-identity.py` and adds the EV columns). Runs from
  the master `make seed STAGE=...` target.
- **Consumers (cross-links via the `vins` dimension)**:
  - [`vehicle_telemetry_aggregated`](../vehicle_telemetry_aggregated/README.md)
    — telemetry's `drive_type` / `powertrain_type` / `vss_version`
    must agree with this product's per-VIN values.
  - [`energy_usage`](../energy_usage/README.md) — supplies
    `battery_pack_kwh` and `manufacture_date` (→ `battery_age_days`)
    that explain SoH decline + efficiency.
  - [`charging_sessions`](../charging_sessions/README.md) —
    `connector_type` and `max_charging_rate_kw` here cap the
    `peak_power_kw` observed in `charging_sessions` for the same VIN.
  - [`ota_campaigns`](../ota_campaigns/README.md) — `target_make` /
    `target_model` / `target_model_year_min/max` filters in the
    header table use this product's `make` / `model` / `model_year`
    columns.
  - [`service_records`](../service_records/README.md) — joins on
    `vin` to enrich service events with vehicle profile.
- **Lineage trace**: `SELECT * FROM
  adp_staging_vehicle_identity."vehicle_identity$snapshots"
  ORDER BY committed_at DESC LIMIT 5`. See
  [`cvx-integration-contract.md` § 6](../../../../docs/cvx-integration-contract.md).

## Data-quality summary

- **Row count**: 5M (1:1 with `vins` dimension); subset by
  `--scale` for dev runs. `len(vehicle_identity) ==
  len(vins) == 5_000_000` is the assertion.
- **EV-coverage**: `powertrain_type = 'electric'` for ~85% of VINs,
  `hybrid` ~10%, `erev` ~5% — matches the EV-startup narrative
  used across products.
- **Edge-case injection** (1–3% per-product band per the six-code
  taxonomy in [`docs/tech.md`](../../../../docs/tech.md)):
  - `missing_required` 0.75% on numeric edge_case_eligible columns
    (e.g. `range_epa_mi`)
  - `late_arrival` 0.50%
  - `schema_drift` 0.35% (`DRIFT-` prefix on enum columns)
  - `bad_pii` 0.20% — `vehicle_identity` declares no
    `pii_drift_target` column; `vin` is FK and never corrupted, so
    this is a **structural zero** here (see Fix Group C in
    [`tasks.md`](../../../.kiro/specs/2026-05-28-adp-ev-startup-foundation/tasks.md))
  - `outlier_value` 0.40% on `range_epa_mi`
  - `orphan_fk` 0.00% (counter-example)
- **FK closure**: `vin` 100% (1:1 with the `vins` dimension by
  construction). Verified by
  `tests/test_referential_integrity.py::test_zero_orphan_vins`.
- **Internal consistency**: `build_software_version ≤
  current_software_version` per the semver-comparison contract;
  `connector_type` mix matches the `vins` dimension's NACS / CCS1 /
  J1772 distribution.
- **Profiling**: `quality-reports/vehicle_identity/profile.{json,md}`
  generated by [`scripts/profile-data.py`](../../../scripts/profile-data.py)
  and surfaced on the CloudWatch dashboard
  `adp-{stage}-foundation-data-quality`.
