# Production Hardening Guide

This reference accelerator ships with certain security features **suppressed** to keep the
out-of-the-box deployment cost and complexity low. Before moving to a production environment,
operators should evaluate and enable the following hardening steps.

## 1. WAFv2 Web ACL for the Predict API (APIG3)

**What it is**: The `/predict` API Gateway endpoint is suppressed from
`AwsSolutions-APIG3` (WAFv2 association) because adding a WAFv2 Web ACL introduces
~$5/month baseline cost plus per-request charges, which is unnecessary overhead for a
reference deployment.

**Why you should enable it in production**: The predict endpoint is an authenticated
(IAM/SigV4) ML inference API. In production, WAFv2 provides:
- Rate-based rules to defend against credential stuffing / API abuse even from valid IAM
  principals.
- AWS Managed Rule Groups (e.g., `AWSManagedRulesCommonRuleSet`) for OWASP Top 10
  protection.
- Logging / visibility into blocked requests via AWS Firewall Manager.

**How to enable**: Create a WAFv2 Web ACL scoped to `REGIONAL` and associate it with the
API Gateway stage. CDK pattern:

```python
from aws_cdk import aws_wafv2 as wafv2

web_acl = wafv2.CfnWebACL(self, "PredictApiWebAcl",
    scope="REGIONAL",
    default_action=wafv2.CfnWebACL.DefaultActionProperty(allow={}),
    visibility_config=wafv2.CfnWebACL.VisibilityConfigProperty(
        cloud_watch_metrics_enabled=True,
        metric_name="PredictApiWebAcl",
        sampled_requests_enabled=True,
    ),
    rules=[
        # Add AWS managed rule groups here; e.g. AWSManagedRulesCommonRuleSet
    ],
)

wafv2.CfnWebACLAssociation(self, "PredictApiWebAclAssociation",
    resource_arn=f"arn:aws:apigateway:{self.region}::/restapis/{api.rest_api_id}/stages/{stage_name}",
    web_acl_arn=web_acl.attr_arn,
)
```

Remove or update the `AwsSolutions-APIG3` NagSuppression comment in
`ml_realtime_inference.py` when enabling this.

## 2. Glue Job Security Configuration (GL1)

**What it is**: The root ETL Glue job (`root-etl-stack/etl-glue-jobs/etl-glue-job`) is
suppressed from `AwsSolutions-GL1` (Glue security configuration for CloudWatch log
encryption). The suppression rationale: Glue security configurations are account-level
shared infrastructure; provisioning a per-stack security config would duplicate KMS CMK
and IAM Glue policy management already owned by the platform-foundation governance stack.

**Why you should enable it in production**: A Glue security configuration enables
server-side encryption for CloudWatch Logs generated by the Glue job, and for job bookmark
data (GL3). In a production environment — particularly one handling sensitive tire telemetry
— encrypting job execution logs reduces the surface area for log-exfiltration attacks.

**How to enable**: Create a `GlueSecurityConfiguration` in the foundation governance stack
(or a shared security stack) and pass its name as a parameter to the ETL Glue job. CDK
pattern:

```python
from aws_cdk import aws_glue as glue

# In your shared/governance stack:
security_config = glue.CfnSecurityConfiguration(self, "GlueSecurityConfig",
    name=f"adp-{stage}-glue-security-config",
    encryption_configuration=glue.CfnSecurityConfiguration.EncryptionConfigurationProperty(
        cloud_watch_encryption=glue.CfnSecurityConfiguration.CloudWatchEncryptionProperty(
            cloud_watch_encryption_mode="SSE-KMS",
            kms_key_arn=glue_kms_key.key_arn,
        ),
        job_bookmarks_encryption=glue.CfnSecurityConfiguration.JobBookmarksEncryptionProperty(
            job_bookmarks_encryption_mode="CSE-KMS",
            kms_key_arn=glue_kms_key.key_arn,
        ),
        s3_encryptions=[
            glue.CfnSecurityConfiguration.S3EncryptionProperty(
                s3_encryption_mode="SSE-KMS",
                kms_key_arn=glue_kms_key.key_arn,
            )
        ],
    ),
)

# Export the config name for consumption by the ETL stack:
CfnOutput(self, "GlueSecurityConfigName", value=security_config.name,
          export_name=f"adp-{stage}-glue-security-config-name")
```

In `etl_glue_jobs.py`, add `security_configuration=<config_name>` to the `CfnJob`
properties and remove (or update) the `AwsSolutions-GL1` and `AwsSolutions-GL3`
NagSuppressions.

## Summary: suppressed-by-default items

| cdk-nag rule | Resource | Reason suppressed in reference | Production action |
|---|---|---|---|
| `AwsSolutions-APIG3` | `realtime-inference-api / dev stage` | Optional for reference; ~$5/mo WAFv2 baseline cost | Associate a WAFv2 Web ACL per §1 above |
| `AwsSolutions-GL1` | `root-etl-stack / etl-glue-job` | Glue security config is shared account-level infra; no per-stack config provisioned | Create a shared Glue security config per §2 above |
| `AwsSolutions-GL3` | `root-etl-stack / etl-glue-job` | Job bookmark encryption depends on the same security config as GL1 | Resolved by the same GL1 fix per §2 above |

All other cdk-nag findings for this accelerator are either fixed in code or suppressed with
specific per-resource justifications documented in the source. See
`source/infrastructure/lib/constructs/` for the inline NagSuppression rationale strings.
